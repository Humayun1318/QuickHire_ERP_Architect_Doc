3.6 — Relationships & Cardinality Map

  • 👤
    User → SeekerProfile (1:1)

    প্রতিটি seeker role user এর একটি মাত্র seekerProfile থাকবে। users.profileId → seekerProfiles._id

  • 🏢
    User → Company (1:1 for owner, M:M for members)

    একজন employer একটি company create করতে পারবেন। কিন্তু company-তে multiple team members যোগ করা যাবে। companies.members[] → users[]

  • 📋
    Company → JobListings (1:M)

    একটি company অনেক job post করতে পারবে। jobListings.companyId → companies._id

  • 📝
    User (Seeker) → Applications (1:M)

    একজন seeker অনেক job-এ apply করতে পারবে। applications.applicantId → users._id

  • 🔗
    JobListing → Applications (1:M)

    একটি job listing-এ অনেক application আসতে পারে। applications.jobId → jobListings._id

  • 📄
    Application → Interview (1:1)

    একটি application থেকে একটি interview schedule হতে পারে। interviews.applicationId → applications._id

  • 💳
    User → Subscription (1:1 active)

    প্রতিটি user এর একটি active subscription থাকবে (free default)। users.subscriptionId → subscriptions._id

  • 💰
    Subscription → Payments (1:M)

    একটি subscription এর lifetime-এ অনেক payment হতে পারে (renewal)। payments.subscriptionId → subscriptions._id

  • 📁
    User → Resumes (1:M)

    একজন seeker multiple resume রাখতে পারবেন, একটি default হবে।

  • 🔔
    User → Notifications (1:M)

    প্রতিটি user এর অনেক notifications থাকতে পারে। Redis Pub/Sub দিয়ে real-time deliver হবে।

Layered System Architecture

Enterprise architecture তে 5-layer pattern follow করতে হবে। প্রতিটি layer এর নিজস্ব responsibility থাকবে — কোনো layer অন্য layer এর কাজ করবে না।

🌐 Layer 1 — Client / Frontend (Next.js / React)
Job Seeker App Employer Dashboard Admin Panel Mobile App (Future)
🔀 Layer 2 — API Gateway / Route Layer (Express.js)
Route Handlers Middlewares (Auth, RateLimit, CORS) Request Validation (Zod) Error Handler
⚙️ Layer 3 — Business Logic / Service Layer
Auth Service Job Service Application Service Payment Service Notification Service Search Service
🗄️ Layer 4 — Data Access / Repository Layer
User Repository Job Repository Application Repository Payment Repository Base Repository (Generic CRUD)
💾 Layer 5 — Persistence & Cache
MongoDB (Primary DB) Redis (Cache + Session + Pub/Sub) Cloudinary / S3 (File Storage) NodeMailer (Email)
💡 Why Repository Pattern? Repository pattern ব্যবহার করলে business logic database থেকে decoupled থাকে। MongoDB থেকে PostgreSQL-এ migrate করলেও শুধু repository layer পরিবর্তন করতে হবে, service layer unchanged থাকবে।

Authentication & Authorization System

JWT Dual Token Strategy

তোমার existing JWT implementation কে enterprise standard এ upgrade করতে Access Token + Refresh Token dual strategy ব্যবহার করতে হবে।

Login Request

User credentials Zod দিয়ে validate, Passport Local Strategy দিয়ে authenticate

Token Generation

Access Token (15min expiry) + Refresh Token (7d expiry) generate করো। Refresh Token MongoDB-তে store করো (refreshTokens collection) + Redis-এ cache করো

Cookie Setup

Access Token → httpOnly secure cookie। Refresh Token → httpOnly secure cookie with longer maxAge

Request Handling

প্রতিটি protected route-এ authenticateToken middleware — cookie থেকে Access Token verify করবে

Token Refresh

/auth/refresh endpoint — Refresh Token validate করে নতুন Access Token issue করবে। Redis-এ token valid কিনা check করবে

Logout

MongoDB থেকে Refresh Token delete + Redis থেকে invalidate + Cookie clear

Payment Integration — SSL Commerz

SSL Commerz Bangladesh-এর most popular payment gateway। নিচে complete payment flow design করা হলো।

Initiate Payment

User plan select করে → POST /payments/initiate → Server SSL Commerz API call করে session তৈরি করে। MongoDB-তে pending payment record তৈরি হয়। SSL Commerz payment URL return করে।

User Pays

User SSL Commerz gateway-এ redirect হয়। bKash/Card/Nagad দিয়ে payment করে।

IPN (Instant Payment Notification)

SSL Commerz তোমার /payments/ipn endpoint-এ POST করবে। তুমি তখন transaction validate করবে SSL validation API দিয়ে। Payment status update করবে DB-তে।

Success / Fail Redirect

User success/fail page-এ redirect হবে। /payments/success এবং /payments/fail handler করতে হবে।

Subscription Activation

Payment success হলে subscription status active হবে। User কে email notification পাঠানো হবে। Redis-এ user session cache invalidate হবে।

⚠️ Security Note IPN endpoint validate করার সময় অবশ্যই SSL Commerz validation API ব্যবহার করো। শুধু IPN data trust করবে না — always server-side verify করো tran_id দিয়ে।
📦 Required Package npm install sslcommerz-lts — Official SSL Commerz Node.js SDK। অথবা manual API call করতে পারো axios দিয়ে।
